# 总揽监测地图性能根因与实测

**日期：** 2026-08-04
**验收视口：** 1920×1080
**页面：** `http://127.0.0.1:63200/#/overview`

## 根因结论

后端不是当前瓶颈。正式后端预热后的总览接口响应约为 4–31ms；总体三级边界响应约 525KB。浏览器性能标记显示，旧实现的 768ms 场景构建中有 737ms 消耗在前端几何 CPU：三个地市边界先联合成 17,065 顶点的地层面，随后该联合面与各地区命中面都被重复做 `THREE.ShapeGeometry` 三角化。

## 已实施的结构优化

- 真实子区多边形共享同一屏幕纹理坐标和地表材质，直接组成连续顶面；联合几何只负责生成连续外侧地层壁，不再重复生成第二张复杂顶面。
- 可见真实边界、选中浮雕和地层侧壁保留展示精度；鼠标射线拾取使用独立的真实面内简化网格，避免为了命中检测再次三角化全部高清顶点。
- GeoJSON 与点位解析按不可变地区对象缓存；同一正式边界在返回上级或重复访问时不再重复 `JSON.parse`。
- 地层联合结果按首个真实几何对象和兄弟行政代码集合缓存；返回已访问层级不重复执行 Turf union。
- 地图切换继续保留上一帧，只有新场景首帧完成后才原子替换，避免蓝色空白或闪烁。

以上优化只作用于 1920×1080 展示几何、命中几何和渲染生命周期，不修改后端/PostGIS 中的源 GeoJSON，也不生成或补画行政边界。

## 1920×1080 浏览器实测

| 指标         | 修改前 |   修改后 |         变化 |
| ------------ | -----: | -------: | -----------: |
| 总体场景构建 |  768ms |    282ms |       -63.3% |
| 总体几何构建 |  743ms |    271ms |       -63.5% |
| 总体几何 CPU |  737ms |    264ms |       -64.2% |
| 首帧渲染     |    6ms |      7ms |       无回退 |
| 县区场景构建 |  179ms | 约 179ms | 已低于 200ms |

总体显示轮廓仍有 29,874 个投影顶点；独立射线命中网格为 12,530 个顶点。数字来自页面 `data-*` 性能标记，便于后续浏览器验收重复读取。

## 性能门禁

- 总体冷场景 `buildDurationMs < 350`；
- 普通县区场景 `buildDurationMs < 250`；
- `firstRenderDurationMs < 50`；
- 切换期间旧画布保持可见，新画布仅在 `data-style-state=ready` 后替换；
- 后端总览读取预热后不高于 100ms；
- 不得通过静态截图、虚构几何或删除真实边界来满足性能指标。
