# 总揽监测 Open MCT 领导演讲指挥中心设计

## 1. 目标

总揽监测不是业务填报页面的集合，而是统一的领导讲解入口。领导打开一次页面，即可围绕年度粮食商情完成“全域态势、地区差异、供需平衡、年度变化、村级档案”的连续讲解，不需要在产情、市场、物流、供需等业务模块之间往返切换。

正式界面只展示业务平台真实填报并符合审核口径的数据。效果图、前端代码、地图文件和配置文件不得承载演示业务数值。没有数据时显示明确空态，不补零、不推算、不使用示例值。

## 2. 使用场景

- 1920×1080 大屏或会议室投屏。
- 领导面向外部来访人员进行 3–10 分钟讲解。
- 默认以全局态势开场，可点击地图或对象树进入县区、乡镇和行政村。
- 需要核对来源时，可从摘要进入原业务模块的完整台账。
- 年度是全屏统一上下文，所有指标、地图状态和图表随年度切换。

## 3. Open MCT 架构映射

采用 NASA Open MCT 的大型任务控制中心信息架构，不引入第二套业务后台。

| Open MCT 概念             | 粮食商情平台映射                             |
| ------------------------- | -------------------------------------------- |
| Mission / Domain Object   | 全局、县区、乡镇、行政村、供需平衡、年度对比 |
| Object Tree               | 领导讲解目录与行政区层级                     |
| Display / Flexible Layout | 总揽任务画布与组件编排                       |
| Inspector                 | 当前地区关键档案与业务摘要                   |
| Time Conductor            | 年度、上一年度和期间控制                     |
| Telemetry Provider        | 正式后端总揽聚合 API                         |
| Status / Notifications    | 数据审核状态、异常和更新时间                 |
| View Provider             | 地图、指标、趋势、结构和同比视图             |

Open MCT 源码为 Apache-2.0。复制或改编的代码保留许可证、版权和来源声明。

## 4. 屏幕信息架构

### 4.1 顶部任务栏

- 平台名称与“总揽监测”任务名称。
- 当前讲解状态：全局 / 县区 / 乡镇 / 行政村。
- 区域、产品、年度三个全局筛选条件。
- 已审核数据状态、数据更新时间和全屏演讲入口。

### 4.2 左侧对象树

对象树用于控制讲解顺序，而不是展示数据库菜单：

1. 全域粮情态势
2. 地区生产与购销
3. 供需平衡
4. 年度变化与同比
5. 县区、乡镇、行政村档案

演讲模式默认收窄对象树；需要跳转讲解对象时展开。行政区从正式行政区主数据动态构建，不写死节点。

### 4.3 中央任务画布

- 第一视觉中心为真实行政边界三维地图，只展示正式监测范围。
- 地图颜色表达已审核数据状态、异常状态和无数据状态。
- 地图上方或周边只展示 4–6 个能概括全局的核心指标。
- 点击行政区后不跳转页面，而是更新全屏讲解上下文。
- 全局状态展示全域概括；地区状态展示当前地区关键结论。

### 4.4 右侧 Inspector

Inspector 只展示当前讲解对象的关键摘要：

- 基础档案：行政层级、代码、数据来源和更新时间。
- 粮食生产：播种面积、总产量等已审核核心指标。
- 购销库存：价格、收购量、销售量和库存等已审核摘要。
- 供需平衡：总供给、总使用、采用后期末库存、库存核对差额。
- 来源入口：进入对应业务台账查看完整记录。

明细表、编辑字段和审核表单不进入总揽默认视图。

### 4.5 底部时间与分析区

Time Conductor 以年度为主控制，明确显示“所选年度”和“上一年度”。核心分析固定为：

- 近 12 月价格走势。
- 品种结构。
- 各地区播种面积同比。
- 各地区总产量同比。

同比由后端按所选年度和上一年度同期的已审核记录计算；任一期间缺少数据时显示缺失状态，不将缺失数据当作零。

## 5. 演讲叙事流程

1. **全局开场**：一句话年度结论、核心指标和全域地图。
2. **地区对比**：点击县区，地图、摘要和同比视图同步切换。
3. **供需说明**：展示供给、使用、期末库存和核对差额之间的关系。
4. **年度变化**：对比所选年度与上一年度的面积和产量。
5. **基层举例**：进入乡镇或行政村，展示其关键业务档案。
6. **来源证明**：需要时进入原业务台账，不在总揽中展开所有明细。

## 6. 数据架构

总揽前端只调用正式后端聚合接口，不直接连接数据库：

```text
业务模块填报与审核
  ├─ 产情监测
  ├─ 市场购销
  ├─ 物流监测
  └─ 供需平衡
          ↓
正式后端总揽聚合服务
  ├─ 审核口径校验
  ├─ 行政区递归聚合
  ├─ 年度与同比聚合
  └─ 数据来源与更新时间
          ↓
Open MCT 风格总揽任务画布
```

所有聚合都受产品、年度、行政区和正式监测范围约束。行政边界来自治理后的真实边界数据。供需平衡只读取正式计算结果。

## 7. 状态与错误处理

- 加载中：保留屏幕结构，使用骨架和“正在读取正式数据”。
- 无数据：显示“当前年度/地区暂无已审核填报数据”。
- 部分数据：仅展示有审核来源的指标，并标识缺失域。
- 接口失败：展示错误状态，不回退到缓存演示数据。
- 边界缺失：不绘制伪造多边形，提示边界待治理。
- 异常：只显示来源于正式业务状态或审核规则的异常。

## 8. 实施边界

- 保留现有 React 正式前端和 Spring 正式后端。
- 复制并适配 Open MCT 的任务控制信息架构、布局模式、时间控制和状态交互；不整体引入 Vue 业务应用。
- 三维行政区视图使用完全开源的 WebGL 地图能力实现，并遵循 Open MCT View Provider 的组件边界。
- 旧仓库只读；正式前端、后端和基础设施继续分离。
- 删除“五个自有库库存/入库/出库”需求。
- 不在总揽中复制业务填报、编辑和审核功能。

## 9. 验收标准

- 1920×1080 下首屏无关键内容溢出，适合投屏。
- 在一次页面会话中完成完整讲解，不依赖业务菜单来回切换。
- 年度切换后，所有指标、地图状态、供需摘要和图表统一更新。
- 点击县区、乡镇、行政村后，全屏上下文一致。
- 页面不存在效果图演示数值或硬编码业务结果。
- 每个展示值可追溯到正式业务记录、正式计算结果或治理主数据。
- 无数据、部分数据、接口失败和边界缺失均有明确状态。
- 目标测试、类型检查、一次正式构建和 1920×1080 浏览器实拍通过。
