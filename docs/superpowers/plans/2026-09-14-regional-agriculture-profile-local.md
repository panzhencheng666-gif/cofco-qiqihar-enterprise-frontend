# 地区农业概况自动推算与预测本地实施计划

## 本阶段目标

只扩展“总揽监测 → 地区数据”。用户点击地图地区后，右侧显示玉米、大豆、水稻的当年公开值/缺项补算、种植结构和明年预测，并覆盖地市、区县、乡镇、行政村。样本点和供需平衡保持现状。

## 完成条件

1. 后端提供独立的地区农业档案只读接口，数据与样本点完全解耦。
2. 有公开地区年度数据时按公开数据归一化；缺项由确定性的统计模型补齐，并明确标记“统计值/模型推算”。乡镇和行政村从最近可用上级公开基线按边界面积、耕作和结构权重分摊。
3. 只预测当年尚未公开的数据和明年数据。每项结果返回原始来源、换算过程、计算公式、置信度和误差区间。
4. 农业公报、天气接口和政策网页由后端每日自动检查；保存抓取状态、摘要、哈希和最近成功时间，失败时保留上次成功快照。
5. 前端只在地区数据模式且已选择地图地区时打开右侧农业概况栏，分区显示种植结构、当年补算与明年预测、农业天气、政策影响、来源与计算证明。
6. 后端针对性测试、前端组件/页面/HTTP 契约测试、构建通过；发布至本地托管运行时并从 63182 真实入口验收到乡镇和行政村。

## 实施顺序

1. 先写后端计算器和接口失败测试，固定三品种、种植结构合计、预测年份和来源标记。
2. 实现应用服务与只读接口，复用现有地区年度数据仓储，不改动填报写入链路。
3. 先写前端仓储与侧栏失败测试，再实现类型、HTTP 解析、侧栏和页面取数。
4. 运行针对性测试与构建，分别提交 backend、map 检查点。
5. 增加公开来源证据账本、网页解析器、天气解析器与每日调度器。
6. 安装到本地托管运行时，复查 API 与浏览器交互。
7. 增加结构化地区档案：区域面积、直接下辖、县级地区、乡镇、行政村和主导作物。
8. 将自动任务固定为北京时间每日 08:30，失败来源每小时重试，前端全部使用中文状态与本地时间。
9. 删除业务界面的原始网页正文、JSON、英文状态码和内部边界版本，改为结构化来源凭证与计算链。
10. 扩宽侧栏并提高正文尺寸，以宽屏和窄屏浏览器分别验证无水平截断。

## 边界

不修改样本点模式、地图钻取、业务导航、供需平衡写入、登录权限和现有地区填报接口。业务用户无需为侧栏另行填报；公开数据优先，缺失值和未来值由系统公式自动生成。网页抓取失败不传导为页面不可用。
